# ESP32 工单总览

根据 [架构文档](../architecture.md) 创建，共 **32 张本地工单**：25 张必需工单覆盖 M0～M6，7 张后续扩展待规划。ESP-001 已补充 6 张图片核对，仍等待实物确认与商家资料；ESP-005／006 的消抖与控制器、ESP-012／013 的 C++ 状态响应与写处理、ESP-014／015 的网页与请求协调、ESP-017 的采集调度、ESP-018／019 的配置与自动温控流程、ESP-020 的网页配置与模拟 API 已通过主机或模拟验证，等待设备接入；其余工单尚未实施。工单未同步到远程工单平台，ESP 编号是本地稳定标识，不是远程 Issue 编号。

## 里程碑

| 里程碑 | 数量 | 完成标志 |
|---|---:|---|
| M0 硬件核对 | 3 | 型号、驱动、供电与引脚规格明确 |
| M1 最小程序 | 2 | 可构建烧录，按键 LED 实验通过 |
| M2 本地风扇 | 3 | 统一控制器、默认关闭、本地操作 |
| M3 红外遥控 | 2 | 遥控映射和重复帧处理通过 |
| M4 联网 MVP | 6 | 手机、按键、红外联合验收通过 |
| M5 温度自动控制 | 5 | 采集、持久化、回差及故障处理通过 |
| M6 整体验收 | 4 | 回归、稳定性、文档和交付归档完成 |
| 后续扩展 | 7 | 当前仅为规划入口，不影响 MVP 完成 |

## 执行与关闭规则

- 2026-10-28 用户允许先做可实施部分：ESP-005／006 的硬件无关规则先行实现并在主机测试；此安排不解除板端集成依赖，也不将部分实现标为整单完成。后续范围见 [图片核对与工单开发范围](../hardware-image-review.md)。
- 从 ESP-001 实物和资料核对开始。硬件未知项通过该工单收集，不猜测参数、不提前接电机。
- 依赖是具体工单完成关系，并非所有里程碑必须整体串行；例如红外诊断与控制器开发在各自前提满足后可以独立开展。
- ESP-016 是第一版局域网 MVP 验收入口；ESP-025 是完整入门项目交付入口。
- 状态可变更为：待办 → 进行中 → 已完成；受阻时标记阻塞，并注明需要的资料或前置工作。待规划需先明确范围才能进入待办。
- 每张必需工单均包含目标、范围、交付物、依赖、可执行验收与限制。关闭前填写完成记录；没有实物不能将硬件验收标为通过。
- 工单中的次数与持续时长为拟定的验收标准，不是测量结果；改动时记录理由并与架构约束一致。
- 不设置未经确认的截止日期或负责人。将来配置远程仓库后可用本地编号迁移去重，并回填远程链接。
