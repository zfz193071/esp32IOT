# ESP-012 实现状态 API 与 HTTP 处理基础

- 里程碑：M4
- 状态：进行中（BSD socket 与 HTTP 联合路径通过回环测试，待 ESP32 工具链和实物接入）
- 范围：必需 · 局域网 MVP
- 依赖：[ESP-006](ESP-006.md)、[ESP-008](ESP-008.md)、[ESP-011](ESP-011.md)
- 架构依据：[系统架构](../architecture.md)、[硬件清单](../hardware.md)

## 目标

向网页提供统一且不可缓存的设备快照。

## 实现范围

- 建立 WebAdapter 和 GET /api/v1/state，返回架构定义的完整字段和正确 null 值。
- 设置 Cache-Control: no-store，定义 JSON 错误结构和未知路由／不支持方法响应。
- 限制请求处理占用和输入大小，记录实现中选用的限制值；HTTP 解析不改变状态。

## 交付物

- HTTP 基础、状态序列化、接口样例与针对性检查。

## 验收步骤与预期

- [ ] 查询结果与串口及实际控制输出一致，bootId/revision 可观察。
- [x] 无温度样本时字段按契约返回，不以 0℃冒充有效温度（C++ JSON 与网页跨语言验证）。
- [ ] 重复状态读取不改变模式或输出，本地按键仍能响应。

## 前提与限制

查询参数和 HTTP 错误不能泄露私有配置。

## 完成记录

- 2026-11-01 补充：SocketHttpTransport 实现明确 IPv4 地址监听、非阻塞读写、backlog 2、单客户端、每次最多 256 字节和监听重开。Esp32SocketCloser 将潜在等待的 close 移出主循环，固定两项待关闭容量，关闭异常阻止新增句柄。真实回环 TCP 及 FreeRTOS 主机桩测试通过；目标 SDK 编译、Wi-Fi 生命周期装配和设备耗时未验证。
- 2026-11-01：新增 HttpApiPort，将单客户端接收、增量解析、静态路由、AppLoop 请求移交和响应排队接通。读写每轮最多 256 字节，响应总期限 5000 ms；主机测试覆盖慢读者期间按键接管、响应短写、超时、断开与流水线命令丢弃。见 [HTTP 连接说明](../development/http-connection.md)，真实 socket 与设备验收仍未完成。
- 2026-10-30：新增 `HttpRequestParser.*`，支持分段接收、单次 256 字节预算、头部 2048／正文 1024 字节上限和总计 2000 ms 接收期限。严格检查 CRLF、Host、重复关键头及长度分帧，完整请求仅交付一次；新增碎片、截断、边界、超时和真实写接口串接测试。实际 TCP、响应发送与主循环接入尚未实现，硬件验收项保持未勾选。
- 2026-10-29：补齐状态快照的模式／温度健康／故障一致性校验。自动模式缺少健康样本、自动模式带故障或健康样本带故障时返回 503 `STATE_UNAVAILABLE`，与网页校验保持一致。跨语言测试新增五种矛盾状态，并保留“温控故障后手动开启”的合法场景；板端接入仍待硬件资料。
- 2026-10-28：先行实现硬件无关的 `StateApi`，提供状态 JSON、无缓存响应头要求、404／405 和固定错误结构。
- 输入路径／方法、bootId 与输出大小限制，以及 JavaScript 安全整数边界已明确；HTTP 解析器接收超时、正文上限和消费预算已实现，真实网络读写预算待板端适配。
- 验证：`node --test firmware/test/StateApiTest.mjs`，编译 C++ 输出后经 JSON.parse 与真实网页 validState 校验，覆盖温度 null、故障、转义、locale 与错误边界。
