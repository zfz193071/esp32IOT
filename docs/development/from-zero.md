# 从零运行与排障指南

这份指南对应 ESP-024。当前仓库可运行主机规则测试、网页资源生成和本机模拟预览；尚缺板型、BoardProfile、GPIO、电机驱动、真实温度与红外驱动、ESP32 HTTP 服务及烧录入口。现在不能给出可执行的 ESP32 编译、烧录命令或接线图。实物信息确认后，按 [硬件清单](../hardware.md) 和 [联调流程](esp32-bringup.md) 补全，并从干净目录实测。

## 1. 取得代码与检查工具

仓库使用 Git。已配置 GitHub SSH 访问时，在终端执行：

```sh
git clone git@github.com:zfz193071/esp32IOT.git
cd esp32IOT
node --version
c++ --version
```

没有 SSH 访问时，先在 GitHub 配置自己的访问方式；不要把令牌写进仓库或终端命令。主机测试需要支持 C++11 的编译器，以及支持 `node --test` 和内置 fetch 的 Node.js。2026-10-28 本机验证环境为 Node v22.19.0、Apple clang 15.0.0；这是测试记录，不是已锁定的 ESP32 工具链版本。若命令找不到，先安装对应工具并重新运行版本检查。仓库当前没有依赖安装步骤。

## 2. 验证可运行的软件

在仓库根目录执行：

```sh
sh firmware/test/run-host-tests.sh
node firmware/tools/embed-web.mjs
```

前者应以 `PASS: requested host regression suites (no ESP32 hardware validation)` 结束；编译或规则失败会以非零状态退出，并指出失败项目。需要额外验证本机 HTTP 模拟配置接口时，运行 `sh firmware/test/run-host-tests.sh --with-preview`；它需要本地端口 18313 和 18314 空闲。详见 [回归覆盖清单](regression.md)。

第二条命令应报告嵌入 5 条网页路由，在被 Git 忽略的 `firmware/build/generated/` 生成 `WebAssets.h`、`WebAssets.cpp` 和 `web-manifest.json`。每次修改网页后重跑；它只生成 C++ 资源，尚未产生可烧录固件。生成文件内容与验证方式见 [网页资源说明](web-assets.md)。

## 3. 本机预览手机控制页

在独立终端执行：

```sh
node firmware/tools/preview-server.mjs
```

保持该进程运行，访问 `http://127.0.0.1:8312`。页面显示“模拟设备预览”；控制操作仅修改内存中的模拟状态。端口被占用时，可在**启动前**为 `ESP32_PREVIEW_PORT` 指定一个空闲端口，并访问对应地址。预览服务仅监听本机，电脑退出后即停止；它不是 ESP32 的局域网服务。网页操作规则见 [手机控制页面](web-control.md)。

## 4. 实物准备与板端联调顺序

先对照 [图片核对](../hardware-image-review.md) 与到货实物，确认主控、底板版本、USB 转串口、电机、驱动、电源、红外接收器和温度器件。蓝色 A2 板与黑色 ESP32 底板是不同线索。取得同版本原理图、电机及驱动规格后填写 [GPIO 与接线登记表](../hardware.md)；在此之前不要按商品图推测引脚或给电机接线。

实物确认后按下列顺序推进，每一步记录固件提交、板型、构建工具版本和观察结果：

1. ESP-004 锁定实际板型与 Arduino-ESP32 核心版本，补建板端构建入口和串口启动日志；电机保持断开，首次编译上传最小固件。
2. ESP-005／007 核对按键与 LED 的 GPIO、有效电平及电机驱动上电关闭方案；先验证输入与 LED，再按已确认的供电方案接入电机。
3. ESP-009／010 实测遥控协议、地址、命令码和重复周期，再配置红外映射；不使用主机测试中的合成编码。
4. ESP-011～016 接入真实 Wi-Fi 与 HTTP 服务，将生成的网页资源编译进固件；串口记录设备实际 IP，用处于同一 Wi-Fi 的手机访问该 IP。
5. ESP-017～021 接入真实温度器件和持久化；验证回差、失效关闭、手动接管、保存与重启恢复。最后按 [压力与连续运行验收](pressure-validation.md) 执行 ESP-023。

板端 Wi-Fi 适配器实现后，把 `firmware/config/wifi.example.h` 复制为同目录 `wifi.local.h` 并填写本地凭据；该文件已被 Git 忽略。当前主机测试与模拟预览不会读取它。串口和报告不要打印密码。网页显示的开关状态是控制信号状态，不代表检测到电机实际转速。

## 5. 按现象排查

| 现象 | 首先核对 | 下一步证据与归属 |
|---|---|---|
| 主机测试无法启动 | `node --version`、`c++ --version`、是否位于仓库根目录；看第一个 `FAIL` 或编译错误 | 对照 [回归说明](regression.md)，记录完整失败项目和工具版本；不要把主机编译器报错当成烧录失败 |
| 预览页打不开 | 预览进程是否仍在运行、终端报告的端口、访问地址是否为本机 `127.0.0.1` | 端口冲突时换空闲端口重启；模拟页面与 ESP32 IP 是两个地址 |
| 修改网页后设备仍显示旧页面 | 是否重新运行资源生成、重新编译并上传固件，查看生成清单 | 读取设备响应与构建版本；本机预览直接读源文件，不能证明设备资源更新 |
| 找不到串口或上传失败 | 数据 USB 线、实际板型、USB 芯片、串口是否被其他程序占用、电源 | 记录上传工具完整报错；按 [联调流程](esp32-bringup.md) 和板卡资料检查下载模式，ESP-004 处理 |
| 设备没有 IP 或手机打不开 | 串口的连接状态与 IP、Wi-Fi 凭据是否已在板端接入、手机是否在同一局域网 | 区分 Wi-Fi 未连接、HTTP 未启动与浏览器请求失败；检查网络适配及 [连接调度](network-service.md)，ESP-011～016 处理 |
| 网页写入被拒绝或显示旧状态 | 请求的 Host／Origin、设备当前 IP、页面是否正在等待同步、串口命令来源 | 查询 `GET /api/v1/state`，结合 [写接口](write-api.md) 和 [网页请求规则](web-control.md) 定位；不要为修复而接受任意跨源写入 |
| 按键／红外不响应 | 已验证的引脚、电平、红外协议／地址／码、串口输入事件 | 先看输入是否产生事件，再看控制器来源和输出；ESP-005、009、010 分别处理 |
| 电机不转、复位时误转或 LED 不一致 | **先断开电机供电**，核对驱动、电压、电流、共地和启动默认关闭方案 | 核对 GPIO 控制信号与实际驱动输出；记录复位／烧录瞬态，ESP-002／007 处理。状态 JSON 不能证明风扇转动 |
| 自动模式不可用或温度异常 | 传感器型号、接线、上拉、采样健康与年龄；页面是否显示有效温度 | 检查故障后自动退出、手动仍可用和恢复不自动重启，ESP-017～021 处理 |
| 阈值保存失败或重启丢失 | 配置 API 返回值、板端存储适配是否已实现、存储初始化日志 | 检查两个阈值是否原子保存和重新加载；当前模拟预览只在内存保存，ESP-018／020 处理 |

每次排障记录触发动作、设备状态、串口时间线、固件提交与接线版本，再复测同一场景。硬件尚未核实或无法提供日志时，记录“未执行／待确认”，不写成已通过。
