# 网页温控配置与模拟接口

ESP-020 的网页表单、请求协调和本机模拟配置 API 已实现。实际 ESP32 的 PUT 路由、ConfigStore 持久化装配、温度采集与断电恢复仍未实现；模拟器把配置保存在进程内存，重启预览进程会恢复默认阈值。

## 使用流程

页面“设备当前阈值”展示最近同步的设备状态，“温控设置”表单保存独立编辑值。输入开启和关闭温度后点击“保存阈值”，两个字段一起提交到 `PUT /api/v1/config`。

两个值都必须填写，范围为 0～60℃，开启温度至少高于关闭温度 1℃。支持小数。点击“使用设备值”仅放弃草稿并加载最近同步值，不发送保存请求。

轮询及设备重启后的状态同步不会覆盖未提交的草稿。保存期间表单和其他写操作禁用，复用现有单写请求机制。只有请求被确认、查询恢复成功、启动标识未改变且同步值与本次提交相符，才显示保存确认。否则保留草稿并提示核对设备值，不自动重发命令。写入响应丢失后即使读取到相同值，也不宣称收到保存确认。

页面增加传感器健康和样本年龄展示。无效温度、过期样本和故障文案使用现有状态快照，实际恢复和自动准入仍由控制器决定。失联时整个状态区只代表历史记录。

## 接口与错误

请求示例：`{"onThresholdC":35.5,"offThresholdC":32}`。模拟 API 严格拒绝缺失字段、多余字段、字符串类型及非法范围，不部分更新。成功返回完整状态，重复值不推进版本。

`400` 表示参数错误，`503` 配合 `STORAGE_FAILURE` 表示保存失败并保留旧配置。客户端显示失败后重新查询，不显示成功。只有约定的存储失败响应才有“保留原配置”语义；一般网络或服务错误视为结果未知。

同源规则沿用模拟服务器的 Host／Origin 校验，非 JSON 写入被拒绝。这不是 ESP-013 的板端实现，也不替代其后续验收。

## 本机运行与故障验证

```sh
# 正常模拟，配置只保存在内存
ESP32_PREVIEW_PORT=8313 node firmware/tools/preview-server.mjs

# 独立故障模拟：合法且有变化的配置保存返回 503
ESP32_PREVIEW_PORT=8314 ESP32_SIMULATE_STORAGE_FAILURE=1 node firmware/tools/preview-server.mjs

# 全部主机测试，无需开放本地端口
sh firmware/test/run-host-tests.sh

# HTTP 集成测试，临时使用 18313 和 18314 端口并自动停止测试进程
node --test firmware/test/PreviewApiTest.mjs
```

正常预览为 `http://127.0.0.1:8313`，故障预览为 `http://127.0.0.1:8314`。如端口已被占用，先确认对应进程归属，不关闭其他任务服务。
