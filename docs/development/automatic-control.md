# 自动温控与故障恢复

ESP-019 已在 FanController 中实现回差、自动模式准入、手动接管和故障恢复。温度由主机测试注入，尚未接入 ESP-017 的实际传感器采集，也没有驱动实物电机。

## 温度输入与主循环顺序

`recordTemperature(value, nowMs)` 接收已完成采集并经适配器验证的摄氏温度，记录有效样本时间；NaN 和无穷按无效样本处理。具体器件的量程、断线值、上电占位值与通信校验由 ESP-017 处理，不能仅凭数值有限就将硬件读数判为有效。

`invalidateTemperature(nowMs)` 标记采集失败，保留是否曾有有效样本及其年龄；当前温度变为不可用。`tick(nowMs)` 更新样本年龄，超过 5000 ms 后将健康样本标记为过期。恰好 5000 ms 仍有效。时钟为同一启动内单调的 32 位无符号毫秒计数，允许自然回绕；主循环必须持续运行，不能跨过整个计数周期才再次检查。已经失效的样本不会因时间回绕自动变健康。

App 每轮应按以下顺序串行执行：

1. 提交本轮刚完成的温度采集结果；无新结果时不重复提交旧数值，避免重置样本年龄。
2. 调用 `tick(nowMs)`，完成健康与故障检查。
3. 按接收顺序处理按键、红外、网页命令及已校验的配置修改。
4. 将控制器最终输出交给 FanOutput，发布快照。

控制器方法更新的是逻辑状态，不直接操作 GPIO。适配器不得在各次状态更新中抢先写硬件。`snapshot()` 不读取系统时钟，调用前应完成本轮 `tick()`；调用者若不推进时钟，控制器无法自行发现样本过期。

## 自动与手动规则

- 无有效样本、采集无效或样本过期时拒绝进入自动，拒绝不改变模式、输出、来源或版本。阈值只通过已校验的构造配置或 ConfigStore 更新进入控制器。
- 从手动进入自动时先以关闭为基准计算：温度达到开启阈值才开启。29℃ 时即使此前手动开启，默认 30／28℃ 配置也会关闭。
- 已在自动模式时，温度 ≥ 开启阈值则开，≤ 关闭阈值则关，两者之间保持。重复设置自动模式不重新清零回差状态。
- 显式开关或按键切换立即转手动；切换手动模式本身保持输出。手动输出不受温度变化或 Wi-Fi 断开影响。
- 自动模式下无效／过期温度立即关闭输出、切为手动、设置温度不可用故障，即使故障前输出已经关闭也退出自动。
- 温度恢复后清除故障，不恢复自动、不改变手动输出。故障期间用户仍可手动操作；恢复不会覆盖用户后来下发的手动命令。
- 自动模式下保存新阈值成功后按当前输出与新回差范围立即重算；保存失败不更新阈值，也不重算输出。

## 状态与版本

`hasTemperature=false` 时适配器必须将 `temperatureC` 序列化为 `null`；内部占位 0 不是有效温度。`hasSample=false` 时 `sampleAgeMs` 为 `null`；曾有有效样本时即使后来失效，仍可显示距离最后有效采样的时间。

温度、传感器健康、故障、模式或输出等公开业务状态变化推进 revision。单纯年龄增加，以及相同温度的新样本重置年龄，不推进 revision。一次温度更新或配置修改引发的多个相关变化合并为一次版本推进。

自动阈值导致输出变化或传感器故障关闭时，命令来源记为 `system`；显式模式命令使用调用者来源。温度恢复仅清除故障时保留最近来源。HTTP 适配器仍须遵守网页安全整数边界。
