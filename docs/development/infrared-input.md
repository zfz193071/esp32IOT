# 红外输入与重复帧过滤

ESP-010 已实现硬件无关的 `InfraredInput` 和 AppLoop 接入。当前没有接收器驱动或正式遥控码；测试中的协议 7、地址 42 等均为合成数据，不能用于实物配置。

## 映射与控制

构造时传入 1～3 条 `InfraredBinding`，以协议、地址和命令的完整组合映射 On、Off 或 Toggle。优先采用实测的独立开／关键；只有确认遥控器使用切换键时才配置 Toggle。协议身份由板端适配器归一化为非零值，不能直接假定不同解码库的枚举相同。

空映射、重复的编码组合、无效动作或无效时间配置会禁用输入，`configured()` 返回 false，且不读取端口。启动集成应检查该结果并报告配置问题。未知协议、地址、命令和无效帧不改变控制状态。

AppLoop 按“按键 → 最多一帧红外 → 最多一个 API 请求”的顺序串行执行，所有红外动作通过 FanController，来源为 infrared；切换操作也遵循控制器的手动接管规则。最终只提交一次变化后的输出，输入层不接触电机 GPIO。

## 长按和接收时间

显式 repeat 帧始终不触发动作。同一映射连续收到完整帧，间隔小于 releaseGapMs 时视为长按；重复帧可延长同一按键的连续接收时间。不同的已映射按键可立即执行。未知帧不会重置已记住的按键。

releaseGapMs 和 maxFrameAgeMs 默认均为 250 ms，属于软件初始参数，并非遥控器实测结果。过快的同键二次短按可能被抑制；丢帧间隔达到释放窗口后，完整帧可能被当作新按下。必须根据 ESP-009 的实际重复周期与接收质量调节并验证长按 3 秒和快速短按。时间配置必须大于零且小于 2^31 ms。

`receivedAtMs` 使用与 AppLoop 相同的 32 位毫秒时钟，记录接收时刻，不能用出队时刻代替。超过 maxFrameAgeMs、未来或相对已接收映射帧乱序的帧被丢弃；普通计时回绕已测试。时间差判断要求相关事件间隔小于半个时钟周期，不用于跨越约 24.8 天休眠后的事件恢复。

## 板端端口要求

`InfraredPort.takeFrame` 每次最多交付一帧且不得等待。实际解码适配器需使用有界队列、限制采集和解码工作量，并在队列满时明确丢弃策略。若协议重复帧不携带地址和命令，适配器应关联有效原始帧；无法可靠关联时丢弃，不能猜测身份。协议噪声或校验失败应标记无效。

InfraredInput 和 InfraredPort 的生命周期必须覆盖 AppLoop；循环串行消费，不能让中断直接调用控制器。接收器型号、引脚、电平、解码库和正式映射仍由 ESP-009 确认。
