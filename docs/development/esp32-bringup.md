# C++ 固件与真实 ESP32 联调流程

本项目采用 Arduino-ESP32 与 C++。最终由电脑将代码编译成适配实际芯片的固件，通过 USB 烧录到 ESP32；运行时按键、传感器、Wi-Fi 和网页服务都在设备侧工作。手机只需访问设备地址，电脑不需要一直运行当前 Node.js 模拟服务器。

目前主机测试通过的控制器、消抖、配置、自动温控和页面是可复用部分；仓库尚无完整板端启动入口、BoardProfile、GPIO 驱动、Wi-Fi／HTTP 服务、真实采集与非易失存储装配，不能直接把现有目录作为完整固件烧录。

## 联调前准备

- 确认实际主控模组、开发板版本、USB 转串口芯片及底板原理图；图中 KF56-3A 是资料检索线索，不是已确认接线依据。
- 使用支持数据传输的 USB 线连接电脑。板型和串口要与设备匹配；按识别出的 USB 芯片决定是否需要驱动，不提前安装猜测型号的驱动。[Arduino 上传排查](https://support.arduino.cc/hc/en-us/articles/4403365313810-If-your-sketch-doesn-t-upload)
- 最初保持电机断开。底板供电、跳线和 GPIO 仍按 ESP-001～003 核对，不能用通用 ESP32 引脚图代替实际底板资料。

## 从电脑测试到板端运行

| 阶段 | 我来完成的软件工作 | 你配合的实物操作与通过标志 |
|---|---|---|
| 识别设备 | 核对板型、枚举串口、检查资料 | USB 插拔确认新增串口，提供板卡与芯片照片 |
| 最小固件 | ESP-004 锁定编译工具／核心版本，建立启动与串口日志，编译烧录 | 按需操作 BOOT／复位；重启后串口稳定输出启动信息 |
| 按键与 LED | 按 BoardProfile 接入消抖与 LED，电机保持断开 | 按下释放 20 次、长按 3 秒，核对事件与 LED，记录有效电平 |
| 电机驱动 | ESP-002／007 确认驱动供电与复位关闭，再接入 FanOutput | 按已确认方案连接电机，检查开关、复位和烧录期间默认关闭 |
| 局域网控制 | 接入 Wi-Fi、HTTP API 和生成网页资源，串口输出设备 IP | 手机连接同一 Wi-Fi，访问设备 IP，交替使用网页／按键／红外 |
| 温控与配置 | 接入真实传感器、采集健康与持久化适配 | 改变温度，检查回差；断开传感器检查故障；重启验证只保留阈值 |

Arduino IDE 是官方支持的安装与上传入口，也可在 ESP-004 中选择适合此仓库的命令行构建流程；选定后锁定版本与板卡标识。安装 ESP32 平台包、选择板卡与串口，再编译上传，是基本步骤。[乐鑫安装说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)

当前不写死板型、串口名、Flash 地址或上传命令。硬件确认后会提供项目实际可执行的“构建、烧录、串口监视”三组命令。主机的 `c++` 测试二进制不能烧录到 ESP32，必须使用目标芯片工具链重新编译。

## 日常如何定位问题

串口是第一轮联调的主要观察入口：看启动、模式、命令来源、输出变化、温度状态、错误及设备 IP。串口波特率应与固件配置一致；上传失败时要检查端口是否被其他串口监视器占用。[乐鑫烧录排查](https://docs.espressif.com/projects/esptool/en/latest/esp32/troubleshooting.html)

每次改动按“主机测试 → 重新生成网页资源（如有变化）→ 编译固件 → USB 上传 → 观察串口 → 实物复测”执行。网页是固件内资源时，修改页面也需要重新生成、编译并上传；当前本机模拟页面自动读取文件的行为不能替代这一步。

若上传连接失败，先确认数据线、正确串口、板卡和供电，必要时按实际板卡说明使用 BOOT／复位进入下载模式。不通用套用别的开发板按键步骤，也不默认擦除全部 Flash。[乐鑫安装说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)、[烧录排查](https://docs.espressif.com/projects/esptool/en/latest/esp32/troubleshooting.html)

USB 串口日志足以支持初期定位。以后若需要断点、单步或变量检查，再按实际芯片、板卡和调试接口评估调试器；不能仅凭板上有 Type-C 就认定支持 USB 硬件调试。

## 分工与当前缺项

你负责实际接线、供电、按键、复位、移动传感器和观察电机；我可以在电脑上维护代码、执行支持的构建／烧录工具、读取串口日志、检查网页 API 并根据结果修正实现。设备必须连接到这台可访问的电脑，才能执行实际串口联调；我无法替你物理插线或确认风扇转动。

最有帮助的下一批材料是实际主控与底板正反面清晰照片、KF56-3A 对应商家原理图／例程、电机和电源标签。准备好后先完成 ESP-001～004，进入最小固件联调，再逐步接入现有业务代码。
