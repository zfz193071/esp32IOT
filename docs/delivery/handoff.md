# 首版交付准备清单

本页是 ESP-025 的**交付准备快照**，基于 2026-10-28 的 `b98d773` 及之前提交。当前只有可运行的主机软件与模拟页面，没有可烧录的 ESP32 固件、已验证接线或实物验收报告，因此不能标记为首版发布。

## 当前可复现的内容

| 内容 | 仓库入口 | 已有证据 |
|---|---|---|
| C++ 控制器、按键与红外输入、温度与网络调度、配置和 API 规则 | `firmware/src/` | [主机回归清单](../development/regression.md)；10 个 C++ 测试程序 |
| 网页及固件资源生成 | `firmware/web/`、`firmware/tools/embed-web.mjs` | 5 条路由的逐字节和可重复生成测试；[资源说明](../development/web-assets.md) |
| 本机模拟预览 | `firmware/tools/preview-server.mjs` | 14 项 Node 默认测试及 2 项可选模拟 HTTP 测试；[运行指南](../development/from-zero.md) |
| 模拟输入压力 | `firmware/test/AppLoopPressureTest.cpp` | 20,000 轮模拟调度；[边界与实物记录](../development/pressure-validation.md) |
| Wi-Fi 配置样例 | `firmware/config/wifi.example.h` | 仅占位值；私有 `wifi.local.h` 被 Git 忽略，当前代码尚未读取 |

主机回归入口为 `sh firmware/test/run-host-tests.sh`；要加入本地模拟 HTTP 测试，使用 `--with-preview`。网页资源使用 `node firmware/tools/embed-web.mjs` 生成到被忽略的 `firmware/build/generated/`。构建产物来源、版本和校验方式见 [网页资源说明](../development/web-assets.md)。这些命令与板端编译、烧录是不同步骤。

## 必需工单与发布门槛

[工单总览](../issues/README.md) 是 25 张必需工单的状态来源。当前没有任何一张必需工单可据主机测试关闭：ESP-001 等待实物与资料，ESP-002～004、007、009、016、021 尚待硬件前置或实测；已开展的软件工单仍需板端接入或联合验收；ESP-022～024 还需最终固件回归、连续运行及实物步骤定稿。7 张扩展单 ESP-026～032 保持待规划，不纳入首版门槛。

首版归档前逐项核对并写入结果：

| 门槛 | 现状 | 归档时所需证据 |
|---|---|---|
| M0 硬件、驱动、供电、GPIO | 待确认 | 同版本原理图、实际板卡及电机规格、已核验 BoardProfile 与接线图 |
| M1～M3 构建、烧录、本地与红外控制 | 未实测 | 锁定工具链、可复现构建命令、串口日志、20 次按键／遥控及复位关闭结果 |
| M4 局域网联合验收 | 未实测 | 手机、按键、红外在实际设备上的同步与断网结果，ESP-016 记录 |
| M5 温控和持久化联合验收 | 未实测 | 真实采集、回差、故障恢复及断电／重启阈值恢复，ESP-021 记录 |
| M6 回归与稳定性 | 软件部分通过；硬件未实测 | 最终固件对应的回归结果、至少 2 小时与 20 次实物开关记录，ESP-022／023 记录 |
| 从零复现与交付物 | 主机步骤已有；板端步骤缺失 | 按 ESP-024 从干净目录构建、烧录、操作，并记录固件二进制及校验摘要 |

## 需要补齐的发布记录

归档时填写实际固件提交、板型与 BoardProfile 版本、Arduino-ESP32 核心与依赖版本、构建及上传命令、产物路径与 SHA-256、配置样例、全部验收报告链接、未关闭问题及其影响。当前这些固件字段均为“未生成／未验证”，不能从主机二进制或网页资源清单推算。公开产物前检查不含真实 Wi-Fi 凭据；私有配置留在设备拥有者本地。

下一次推进应从 [ESP-001 硬件登记](../hardware.md) 开始：核对实际主控和底板正反面、USB 芯片、电机／供电标签与同版本商家原理图。依次完成 ESP-002～004、007 的安全接线和最小固件后，现有软件才可逐项装配并在设备上验证。所有仍未执行的验收结果保持空白或“未执行”。
